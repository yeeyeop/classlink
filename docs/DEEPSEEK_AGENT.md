# DeepSeek 教室预约 Agent

## 接入方式

在 `.env.local` 中配置：

```env
DEEPSEEK_API_KEY=你的 DeepSeek API Key
DEEPSEEK_API_URL=https://api.deepseek.com/chat/completions
DEEPSEEK_MODEL=deepseek-chat
DEEPSEEK_TIMEOUT_MS=30000
```

配置后，管理台右侧“教室信息助手”优先调用 DeepSeek。未配置 Key 时继续使用本地实时数据规则，不影响演示和测试。

助手只允许管理员使用。主页面拉手仅在管理员会话下渲染，组件自身也会校验角色，查询、日志和确认执行接口全部返回普通学生 `403`。

## Agent 领域约束

系统提示词只允许助手回答：

- 教室空闲状态、楼层、类型和容量。
- 课程占用情况。
- 学生预约和预约时间。
- 座位、设施和设备状态。
- 预约规则和可操作建议。

助手必须调用工具读取实时业务上下文，不能编造教室、预约、课程或设备数据。对于取消预约、改约等写入操作，助手只给出建议，不声称已经执行，最终操作仍由管理员通过管理台完成。

当对话偏离教室预约时，助手不会生硬拒答，而是统一回复：

> 我们还是接着说和教室预约相关的吧。

随后可以提示当前能够查询空闲教室、课程、预约或设备状态。

## 工具

DeepSeek 可以使用以下只读工具：

| 工具 | 作用 |
| --- | --- |
| `search_rooms` | 按状态、楼层、类型、容量筛选教室 |
| `get_room` | 查看指定教室的详细状态 |
| `list_courses` | 列出当前时段的课程 |
| `list_reservations` | 列出当前时段的有效预约 |
| `get_device_status` | 查看指定教室的设备状态 |
| `get_booking_rules` | 获取预约规则 |
| `prepare_booking` | 生成待管理员确认的预约操作 |
| `prepare_cancel_booking` | 生成待管理员确认的取消操作 |

工具执行在服务端读取实时 JSON 数据，模型拿不到其他用户密码、会话或敏感凭据。

## 回答流程

```text
管理员提问
  → 服务端构建当前日期和节次上下文
  → DeepSeek 选择工具
  → 服务端执行只读工具
  → 工具结果返回 DeepSeek
  → 生成受领域提示词约束的中文回答
```

服务端最多进行 4 轮工具调用，防止模型循环。外部接口超时或返回异常时会自动回退到本地规则回答。

## 真实操作确认

预约和取消采用“两阶段执行”：

1. 模型只能调用 `prepare_booking` 或 `prepare_cancel_booking` 生成操作预览。
2. 助手窗口显示待确认卡片，管理员点击“确认执行”后调用 `POST /api/admin/assistant/actions`。
3. 服务端重新检查管理员权限、使用人、预约日期、节次、课程和冲突。
4. 校验通过后写入数据库并通过 SSE 通知所有在线页面。

模型本身没有直接写数据库的权限，不会在没有确认的情况下修改预约。
