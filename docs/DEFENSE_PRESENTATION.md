# 答辩提纲与讲稿

## 建议 12 页结构

1. 项目背景：教室信息分散，空闲状态不透明。
2. 用户与角色：学生、管理员及各自任务。
3. 总体架构：Next.js 前后端、JSON 持久化、Three.js。
4. 预约闭环：注册登录、实时可用性、预约、取消。
5. 服务端规则：日期、节次、时长、人数、课程和冲突。
6. 管理员能力：全量筛选、调整、恢复、账号和通知。
7. 安全加固：删除独立管理员入口、scrypt、会话过期、真实重置令牌。
8. 数据可靠性：写队列、原子替换、备份恢复。
9. 特色技术：数据驱动 3D 数字孪生。
10. 设备中控：持久化、场景模式与审计。

12. 反思与规划：已知边界、正式部署路线。

## 3 分钟主讲稿

### 开场

我们的项目是北京邮电大学海南校区专享楼 A 座空教室预约平台。它解决的核心问题是：学生无法快速知道哪些教室当前真正空闲，管理员也缺少对全部预约的统一管理入口。

### 业务闭环

学生使用校园邮箱注册并登录，选择日期和节次后，系统会从后端读取该时段的完整可用性。空闲教室可以预约，其他用户已经预约、课程占用、维护和关闭状态都会准确显示。预约、取消、管理员调整后，页面和 3D 状态都会立即刷新。

### 技术重点

所有预约规则只在服务端执行，包括日期格式、过去时段、节次、时长、人数、课程和预约重叠。这样即使绕过页面直接请求 API，也不能写入非法数据。

数据层使用进程内写队列和临时文件原子替换。每次写入前保留备份，出现损坏时不会静默清空数据库。

管理员与普通用户使用同一个登录入口，正式管理员由初始化脚本创建，所有管理员 API 还会再次校验服务端角色。

### 特色技术

我们没有把 3D 当作背景动画，而是将它做成数字孪生。房间颜色来自后端可用性 API，点击房间方块会显示课程、设施和状态，空闲房间可以直接预约。设备中控也改为持久化后端状态，并保留操作日志。

### 验证与收尾

项目提供 17 个领域单元测试、ESLint、生产构建和真实 HTTP 冒烟测试；浏览器还完成了 3D 拾取、UI 预约和取消。主页面右侧的信息助手使用 DeepSeek 领域 Agent，通过工具读取实时数据并准备预约/取消动作，最终执行必须由管理员确认。预约、取消、单人通知、管理调整和设备写入通过 SSE 推送，页面自动刷新。当前版本对原评审中的权限、假流程、假按钮、状态不准确和数据闭环问题都给出了可运行证据。

## 现场演示脚本

1. 打开首页并登录学生账号。
2. 选择明天第 3-4 节，指出空闲、上课和未投入的统计。
3. 预约 205 教室，等待状态变为“我的预约”。
4. 打开 3D 楼宇，点击相同房间，说明后端状态与图形状态一致。
5. 登录管理员账号，演示改约和发送通知。
6. 返回学生账号，在通知中心查看消息。
7. 打开设备中控，应用节能场景并刷新，证明状态持久化。
8. 展示 `npm run verify` 结果和 `npm audit`。

## 可能提问与回答

### 为什么仍然用 JSON？

课程项目需要零外部依赖和便于检查数据。我们通过写队列、原子替换和备份降低了单实例风险，同时在文档中明确多实例上线应迁移数据库。

### 3D 是否只是视觉效果？

不是。3D 房间由真实房间列表构建，颜色读取可用性接口，点击使用 Raycaster 拾取并展示后端状态。预约后状态会变化，有浏览器交互证据。

### 设备是否真的接到硬件？

当前实现是完整软件控制闭环，不是伪造的硬件在线状态。若现场有 MQTT 或 Modbus 网关，可在现有 API 内替换执行层。

### 管理员账号如何创建？

通过 `npm run admin:create` 初始化，密码使用随机盐和 scrypt 哈希。正式部署建议进一步接入 SSO、最小权限和审计日志。

### 如何证明没有假按钮？

每个关键按钮都有对应 API、持久化字段或自动化测试。监控没有真实视频源时明确显示未接入，不再显示伪造的 `LIVE`。
