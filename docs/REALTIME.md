# 实时刷新机制

## 目标

预约、取消、管理员调整、通知或设备状态发生变化后，所有在线页面无需手动刷新即可看到最新结果。

## 实现

1. 数据层在原子写入成功后发布 `db:changed` 事件。
2. 登录用户通过 `GET /api/realtime` 建立 SSE 长连接。
3. 浏览器收到事件后，以 120 毫秒防抖并行刷新可用性、本人预约和通知。
4. 管理台同时刷新预约列表和账号统计。
5. 每 20 秒发送心跳，保持连接存活。
6. 浏览器断线后由 `EventSource` 自动重连，页面显示“重连中”。
7. 60 秒定时查询作为断线兜底。

## 覆盖的数据变化

- 学生创建或取消预约。
- 管理员调整时间、更换教室、取消或恢复预约。
- 管理员向单个学生发送通知。
- 通知标记已读。
- 设备空调、照明、投影和场景状态变化。
- 管理员注销账号导致预约失效。

## 为什么使用 SSE

教室状态主要由服务端向浏览器单向推送，SSE 比 WebSocket 更简单，支持浏览器自动重连和标准事件流。当前项目为单实例 JSON 部署，因此事件总线保存在 Node.js 进程内。

多实例部署时，应把 `lib/realtime.js` 的进程内事件总线替换为 Redis Pub/Sub，并保持 `/api/realtime` 对外协议不变。
