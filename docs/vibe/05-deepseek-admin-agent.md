# Vibe 日志 05：管理员专属 DeepSeek 教室 Agent

## 本次目标

在主页面右侧增加一个可拉出的管理员对话窗口，帮助管理员确认教室空闲、课程、预约和设备信息。模型只回答教室预约领域，能够理解自然语言，并通过真实工具查询后端；不仅要能查询，还要在管理员确认后预约或取消预约，且普通学生完全不可见、不可调用。

## 使用提示词

> 接入 DeepSeek API，但不要只做几个预设关键词。助手要尽量把话题集中在教室预约上；无关话题自然地说“我们还是接着说和教室预约相关的吧”。助手需要能帮我预约、取消预约，先展示动作预览，由我点击确认后才执行。它只能出现在管理员账号，而且位置必须是主页面右侧可拉开的独立窗口，不是管理页里的临时按钮。

## AI 生成结果

- 新增管理员专属 `/api/admin/assistant` 和确认执行接口 `/api/admin/assistant/actions`。
- 使用 DeepSeek OpenAI 兼容接口，配置项包括 API 地址、模型别名、超时和额外领域提示词。
- 提供 `search_rooms`、`get_room`、`list_courses`、`list_reservations`、`get_device_status` 和预约规则查询等只读工具。
- 通过 `prepare_booking` 和 `prepare_cancel_booking` 生成待确认动作，模型不能直接写数据库。
- 主页面加入右侧抽屉，管理台保留助手日志；未配置模型时使用实时数据规则回答。

## 遇到的问题

第一版助手过度依赖固定说法，用户只有输入预设句子才有反应，这会让验收看起来像“假 AI”。用户追问“到底接入了什么模型”后，我们确认本地配置的是 DeepSeek 官方兼容接口，模型别名是 `deepseek-chat`，直接请求时接口返回的模型标识是 `deepseek-flash`；这不是本地微调模型，而是领域提示词、工具调用和权限约束组成的 Agent。

另外，最初把助手放在管理页，用户要求改成主页面右侧可拉开的窗口。模型识别无关话题时语气也过于生硬，迭代后统一为“我们还是接着说和教室预约相关的吧”，再给出可继续追问的教室方向。

## 迭代修改

- 放弃大量 `if/else` 预设，改为真实模型工具调用，工具结果必须来自服务端实时数据。
- 助手上下文包含当前日期、节次、房间状态、课程、预约、设备和规则。
- 预约和取消采用两阶段：先返回动作预览，管理员点击确认后服务端重新校验，再写入数据库并发送 SSE。
- 普通学生访问对话、日志和确认接口全部返回 403；前端按钮与组件自身都检查管理员角色。
- 无关话题不再机械拒答，而是温和收束到教室预约。
- API Key 只写入本机 `.env.local`，日志、源码、PPT 和发布包都不记录密钥值。

## 小组理解

“训练一个 Agent”不一定要重新训练模型。对短周期课程项目，更可靠的方式是明确领域边界、提供可审计工具、限制模型权限，并让每次写操作都经过人工确认和服务端复核。

## 验证证据

- 实测“找适合 10 人以上、当前空闲的教室”触发了 `search_rooms` 工具并返回实时结果。
- 实测无关问题返回“我们还是接着说和教室预约相关的吧”。
- 实测准备并确认预约 `208`、次日第 2 个节次块；随后准备并确认取消，数据库状态正确变化。
- 学生会话访问助手接口返回 403。
- 未配置模型时，本地实时数据规则仍可完成查询并保持演示可运行。
