# Vibe 日志 02：全量可用性、预约规则与 JSON 持久化

## 本次目标

修复两个会直接破坏核心体验的问题：第一，`GET /api/bookings` 只返回当前用户自己的预约，前端却用它判断教室是否空闲，导致他人已经预约时仍显示“空闲”；第二，后端只检查日期和节次类型，直接请求 API 可以写入非法日期、99 节、负时长或超容量人数。

## 使用提示词

> 先解释原预约数据流，再做最小的完整改造。新增全量可用性接口，但不能泄露其他学生的姓名、学号和邮箱。把日期、节次、时长、人数、课程、过去时段和重叠规则集中到服务端可测试模块。预约创建必须在同一个写锁内再次检查冲突，不能只在页面判断。补充非法参数、课程冲突、他人预约和取消后恢复的测试。

## AI 生成结果

- 确认原“我的预约”接口不适合作为全楼宇状态来源。
- 新增 `/api/bookings/availability`，按日期和节次返回脱敏后的房间状态。
- 状态区分为 `free`、`class`、`reserved`、`mine`、`maintenance` 和 `closed`。
- 将预约规则集中到 `lib/booking-rules.js`，学生创建和管理员改约共用同一套校验。
- 在 JSON 数据层增加写队列、临时文件原子替换、备份恢复和损坏文件保留。

## 遇到的问题

最初只补一个“查询所有预约”的接口会带来隐私泄露，也不能解决并发窗口：两个请求可能同时通过冲突检查，随后先后写入。另一个边界是当天已经开始的节次，页面可能因为时区和当前时间计算差异放过，服务端必须再判断一次。

## 迭代修改

- 可用性接口只返回房间、业务状态、是否本人预约和预约标识，不返回其他用户 PII。
- 冲突检测使用半开区间，检查预约覆盖的每一个节次，同时检查课程占用。
- 创建、管理员改约和取消都在数据层临界区内重新执行规则。
- JSON 写入改为“临时文件写完后替换”，上一版保留为备份；解析失败时不再静默清库。
- 增加日期、节次 99、负时长、零人数、课程冲突、重叠、取消不占位和改约忽略自身等测试。

## 小组理解

“可用性”是从预约、课程和房间状态计算出来的视图，不是另一份可以随意修改的数据。读接口解决展示一致性，写接口解决业务正确性，两者不能用同一份“我的预约”数据代替。

## 验证证据

- 非法日期、节次、时长和人数均返回 400。
- 同一教室同一时段再次预约返回 409。
- 预约后可用性状态为 `mine`，取消后恢复为 `free`。
- 单元测试覆盖合法值、边界值、课程冲突和跨节冲突。
- `npm run smoke` 验证真实 HTTP 数据链路，而不只是调用函数。
