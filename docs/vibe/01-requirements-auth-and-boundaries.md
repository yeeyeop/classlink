# Vibe 日志 01：需求复核、演示入口清理与管理员鉴权

## 本次目标

把评审结论中的 P0 风险先处理掉：匿名调用 `/api/auth/admin-demo` 可以获得管理员会话，前端虽然可能存在入口差异，但真正的权限边界没有建立。目标是删除所有演示入口，让管理员和普通学生共用正式登录链路，并确保每个管理员接口都在服务端复核角色。

## 使用提示词

> 先阅读真实路由、登录组件和管理接口，不要根据文件名猜测。删除所有演示入口，不能让匿名请求创建管理员会话。管理员与学生共用登录表单，管理员账号由初始化脚本创建。逐个检查 `/api/admin/*` 的服务端角色校验，而不是只隐藏按钮。修改后补充旧接口 404、普通学生访问管理员接口 403 的验证。

## AI 生成结果

- 定位并删除旧的匿名管理员演示路由，不再保留可通过 URL 直接访问的后门。
- 新增管理员初始化脚本，读取环境变量或交互参数创建管理员账号。
- 管理员和普通用户统一经过 `/api/auth/login`，页面根据服务端返回的角色跳转。
- 新增统一的管理员会话检查逻辑，并在预约、账号、通知和助手接口中复用。
- 将删除旧演示入口、初始化管理员、普通学生访问管理员 API 纳入 HTTP 冒烟测试。

## 遇到的问题

最初的修改只处理了界面入口，评审人员仍可绕过页面直接调用旧 API，问题并没有消失。另一个风险是旧的演示账号和演示数据可能继续残留在数据库中，导致现场验收时角色和统计结果混乱。

## 迭代修改

- 人工判断明确为“删除接口，不只隐藏按钮”。
- 管理员不再拥有独立登录页面，而是与学生使用同一个表单。
- 旧演示账号及其关联数据在初始化脚本中清理，避免混入正式统计。
- 所有管理员写操作都重新读取会话并校验 `role === 'admin'`。
- 冒烟测试确认旧路径返回 404，普通学生访问助手查询、日志和确认执行接口全部返回 403。

## 小组理解

前端显示控制只是交互设计，不能承担安全职责。权限判断必须发生在服务端，而且要在每次敏感操作时重新执行，不能依赖登录页面或客户端传入的角色字段。

## 验证证据

- 旧 `/api/auth/admin-demo` 路径不再存在，冒烟测试返回 404。
- 管理员初始化后可通过普通登录表单登录，服务端返回 `role=admin`。
- 学生会话调用管理员助手接口返回 403。
- 生产构建通过，管理员路由完成独立构建。
